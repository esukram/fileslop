# ADR-014: Tests with node:test and a mock S3 server

Status: Accepted

Date: 2026-10-29

## Context

Fileslop has no runtime dependencies (see [ADR-001](ADR-001.md)).
The test setup must not add a large framework.
Tests must run locally and in CI without network access and without cloud credentials.
The main risks are in signing, key layout, validation, and the HTTP contract.

## Decision

- Use the Node.js built-in test runner `node:test` and `node:assert`.
- Do not add a test framework dependency.

Unit tests cover:

- AWS Signature V4 with the official AWS example vector.
- ISO week-year and week calculation, also at year boundaries.
- Header validation (see [ADR-009](ADR-009.md)).
- Key file parsing, token hashing, and appends to a key file without a final newline (see [ADR-006](ADR-006.md)).
- Index persistence after a partial last line (see [ADR-005](ADR-005.md)).
- Endpoint resolution for `aws_s3`, `hetzner`, and the endpoint override (see [ADR-003](ADR-003.md)).
- Two concurrent uploads with the same identifier (see [ADR-008](ADR-008.md)).
- The client: the MIME type map (see [ADR-007](ADR-007.md)), the default filename, the git remote parser, the token mask, and the priority of environment variables over the config file.

End-to-end tests in `e2e/`:

- Start an in-process mock S3 HTTP server.
- The mock supports PUT with `If-None-Match: *`, GET, and `x-amz-meta-*` metadata.
- The mock recalculates the Signature V4 signature with the production `sign()` function. A wrong signature or a missing signed header gives 403.
- The mock compares the payload hash with the body. A different hash gives 400.
- Start the real server as a child process. Point it to the mock with `FILESLOP_S3_ENDPOINT`.
- Run the real client CLI as a child process.
- Check status codes, response bodies, headers, stored metadata, and exit codes.
- Check the frontmatter and the length of the agent skill (`e2e/skill.test.ts`).

## Consequences

Positive:

- No network access is necessary. Tests are fast and deterministic.
- Tests use the real server and the real client. They test the contract end to end.
- No test framework dependency.

Negative:

- The mock uses the same `sign()` function as the server. Thus the mock finds a missing or changed signed header, but not an error in the signing algorithm.
  Only the unit test with the official AWS example vector checks the signing algorithm independently.
- CI does not find differences between the mock and real stores.
- A manual test against AWS S3 and Hetzner is necessary before a release.

## Alternatives considered

- Vitest or Jest: extra dependencies. Rejected.
- MinIO in a container: needs Docker in CI and is slower. Rejected for v0.1.
- Tests against real AWS: needs credentials and network. Rejected for CI.
