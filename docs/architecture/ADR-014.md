# ADR-014: Tests with node:test and a mock S3 server

Status: Accepted

Date: 2026-10-29

## Context

Fileslop has no runtime dependencies (see [ADR-001](ADR-001.md)).
The test setup must not add a large framework.
Tests must run locally and in CI without network access and without cloud credentials.
The main risks are in signing, key layout, validation, and the HTTP contract.

## Decision

- Use the Node.js built-in test runner `node:test` and `node:assert`.
- Do not add a test framework dependency.

Unit tests cover:

- AWS Signature V4 with the official AWS example vector.
- ISO week-year and week calculation, also at year boundaries.
- Header validation (see [ADR-009](ADR-009.md)).
- Key file parsing and token hashing (see [ADR-006](ADR-006.md)).
- The MIME type map of the client (see [ADR-007](ADR-007.md)).

End-to-end tests in `e2e/`:

- Start an in-process mock S3 HTTP server.
- The mock supports PUT with `If-None-Match: *`, GET, and `x-amz-meta-*` metadata.
- Start the real server as a child process. Point it to the mock with `FILESLOP_S3_ENDPOINT`.
- Run the real client CLI as a child process.
- Check status codes, response bodies, headers, stored metadata, and exit codes.

## Consequences

Positive:

- No network access is necessary. Tests are fast and deterministic.
- Tests use the real server and the real client. The contract is tested end to end.
- No test framework dependency.

Negative:

- The mock S3 server does not check signatures. Only the unit test with the AWS vector checks the signature code.
- Differences between the mock and real stores are not visible in CI.
- A manual test against AWS S3 and Hetzner is necessary before a release.

## Alternatives considered

- Vitest or Jest: extra dependencies. Rejected.
- MinIO in a container: needs Docker in CI and is slower. Rejected for v0.1.
- Tests against real AWS: needs credentials and network. Rejected for CI.
