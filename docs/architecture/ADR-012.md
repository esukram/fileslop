# ADR-012: Configuration with FILESLOP_ environment variables

Status: Accepted

Date: 2026-10-29

## Context

The server runs in containers and on hosts. The client runs on developer machines and in CI.
Both need a simple configuration without dependencies.
Node.js has `process.loadEnvFile()` to read a `.env` file.

## Decision

- Use environment variables with the prefix `FILESLOP_`.
- Do not use the prefix `FS_`. `FS_` is ambiguous because it can mean "file system".
- The server reads an optional `.env` file with `process.loadEnvFile()`.
- Real environment variables have priority over the `.env` file.
- The sample file is `server/.env.sample`.

Server variables:

| Variable                        | Default    | Description                                                                                       |
| ------------------------------- | ---------- | ------------------------------------------------------------------------------------------------- |
| `FILESLOP_PUBLIC_URL`           | required   | Public base URL, for example `https://files.example.org/fileslop/`. Its path is the route prefix. |
| `FILESLOP_HOST`                 | `0.0.0.0`  | Listen address.                                                                                   |
| `FILESLOP_PORT`                 | `8080`     | Listen port.                                                                                      |
| `FILESLOP_BACKEND`              | required   | `aws_s3` or `hetzner`.                                                                            |
| `FILESLOP_S3_ACCESS_KEY_ID`     | required   | Access key of the object store.                                                                   |
| `FILESLOP_S3_SECRET_ACCESS_KEY` | required   | Secret key of the object store.                                                                   |
| `FILESLOP_S3_BUCKET`            | required   | Bucket name.                                                                                      |
| `FILESLOP_S3_REGION`            | —          | AWS region. Required for `aws_s3`.                                                                |
| `FILESLOP_HETZNER_LOCATION`     | —          | `fsn1`, `nbg1`, or `hel1`. Required for `hetzner`.                                                |
| `FILESLOP_S3_ENDPOINT`          | —          | Endpoint override with path-style URLs. Must be an http(s) URL.                                   |
| `FILESLOP_BASE_DIR`             | `fileslop` | First part of each object key.                                                                    |
| `FILESLOP_DATA_DIR`             | `./data`   | Folder for `index.jsonl` and `keys.txt`.                                                          |
| `FILESLOP_MAX_UPLOAD_BYTES`     | `26214400` | Maximum body size.                                                                                |

Client configuration:

- Environment variables: `FILESLOP_URL` and `FILESLOP_TOKEN`.
- JSON file: `$XDG_CONFIG_HOME/fileslop/config.json`. The default is `~/.config/fileslop/config.json`.
- `FILESLOP_CONFIG` overrides the path of the file.
- The file has the keys `url` and `token`.
- Environment variables have priority over the file.

## Consequences

Positive:

- No configuration library is necessary.
- The configuration works in containers, systemd units, and CI.
- The prefix prevents conflicts with other tools.

Negative:

- The server validates the variables itself. If a variable is missing or invalid, the server stops at start with exit code 2. The message lists all problems.
- Processes of the same user can read secrets in environment variables.
- The container image does not contain a `.env` file. Give the file to the container with `docker run --env-file .env`.
