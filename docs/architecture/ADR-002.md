# ADR-002: Repository layout is a pnpm workspace monorepo

Status: Accepted

Date: 2026-10-29

## Context

Fileslop has four parts: a server, a client CLI, an agent skill, and end-to-end tests.
The parts share one HTTP contract.
A change to the contract must change the server, the client, and the tests together.
One repository lets one pull request change all parts.

## Decision

Use one pnpm workspace with these folders:

| Folder             | Content                                                 |
| ------------------ | ------------------------------------------------------- |
| `server/`          | The HTTP server.                                        |
| `client/`          | The client CLI. The npm package name is `fileslop`.     |
| `skills/fileslop/` | The agent skill (see [ADR-017](ADR-017.md)).            |
| `e2e/`             | End-to-end tests (see [ADR-014](ADR-014.md)).           |
| `docs/`            | Architecture decision records and product requirements. |

- Use the folder name `skills/`, not `skill/`.
- The `npx skills` CLI searches `skills/` as a standard location. Thus `npx skills add esukram/fileslop` finds the skill.
- Keep development tools (TypeScript, ESLint, Prettier) at the workspace root.

## Consequences

Positive:

- One pull request changes the contract, the server, the client, and the tests together.
- One CI workflow tests all parts.
- One lock file controls all development dependencies.

Negative:

- Server and client have one version number and one release tag. A server-only change also creates a new client version.
- Contributors must use pnpm. npm does not read `pnpm-workspace.yaml`.

## Alternatives considered

- Separate repositories for server, client, and skill: contract changes need several pull requests. Rejected.
- Folder name `skill/`: the `npx skills` CLI does not find it automatically. Rejected.
