# ADR-010: Safe delivery of user content

Status: Accepted

Date: 2026-10-29

## Context

Fileslop delivers any file that a user uploads, also HTML with scripts.
HTML plans and reports are a main use case. Their scripts must run.
A script must not read cookies or data of other pages on the same origin.
Stored objects never change (see [ADR-008](ADR-008.md)).

## Decision

A successful GET response has these headers:

| Header                    | Value                                 |
| ------------------------- | ------------------------------------- |
| `Content-Type`            | The stored content type.              |
| `X-Content-Type-Options`  | `nosniff`                             |
| `Content-Security-Policy` | `sandbox allow-scripts`               |
| `Cache-Control`           | `public, max-age=31536000, immutable` |

- `nosniff` stops the browser from a guess of a different type.
- `sandbox allow-scripts` lets scripts run in an opaque origin. The scripts have no same-origin access.
- The long cache time is safe because objects never change.

The server returns status 404 with the error code `not_found` in these cases:

- The identifier is not in the index.
- The filename in the URL is not the stored filename.
- The object is not in the store.

## Consequences

Positive:

- Interactive HTML artifacts work.
- A malicious HTML file cannot read data of the Fileslop origin or set its cookies.
- CDNs and browsers cache objects for one year.

Negative:

- Sandboxed HTML cannot use `localStorage`, cookies, or same-origin requests.
- Forms and pop-ups do not work in sandboxed pages.
- Operators should still serve Fileslop on a separate domain for defense in depth.

## Alternatives considered

- Force download with `Content-Disposition: attachment`: HTML plans do not open in the browser. Rejected.
- Serve HTML as `text/plain`: scripts do not run. Rejected.
- Short cache times: not necessary for immutable objects. Rejected.
