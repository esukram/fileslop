# ADR-011: Upload size limit with an in-memory body buffer

Status: Accepted

Date: 2026-10-29

## Context

The S3 adapter signs the SHA-256 hash of the body (see [ADR-003](ADR-003.md)).
To calculate the hash before the PUT, the server needs the full body.
Typical artifacts (HTML plans, screenshots, logs) are smaller than a few MiB.
An unlimited body can use all memory of the server.

## Decision

- The server buffers the request body in memory.
- The limit is `FILESLOP_MAX_UPLOAD_BYTES`. The default is 26214400 bytes (25 MiB).
- A body larger than the limit gives status 413 with the error code `payload_too_large`.
- The server stops the read when the body becomes larger than the limit.
- An empty body is a valid file with 0 bytes. The server stores it.

## Consequences

Positive:

- The code is simple.
- The signed payload hash protects the body integrity during transfer to the store.
- The limit protects the server against large requests.

Negative:

- Memory use is the limit multiplied by the number of concurrent uploads.
- Files larger than 25 MiB need a change of the configuration and more memory.

## Upgrade path

- Stream the body to the store with `UNSIGNED-PAYLOAD`.
- Use S3 multipart upload for very large files.

## Alternatives considered

- Stream from the first version: more complex signing and error handling. Not necessary for v0.1.
- Write the body to a temporary file: disk use and clean-up. Not necessary for v0.1.
