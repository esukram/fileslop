# ADR-017: Agent skill for uploads and pull request artifacts

Status: Accepted

Date: 2026-10-29

## Context

AI agents create artifacts: HTML plans, screenshots, logs, and reports.
GitHub cannot attach arbitrary files to a pull request.
Agents need short instructions to use Fileslop correctly.
Agent harnesses load skills from a `SKILL.md` file with YAML frontmatter.

## Decision

- Put the skill in `skills/fileslop/SKILL.md`.
- The YAML frontmatter has the fields `name` and `description`.
- Users install the skill with `npx skills add esukram/fileslop`.
- Keep the skill shorter than 80 lines. Agents load it into their context. An e2e test checks the length and the frontmatter.

The skill covers:

- The upload command: `npx -y fileslop upload <file>`.
- The configuration check: `npx -y fileslop config`.
- The use of `--type` for unknown file extensions.
- The meaning of the exit codes (0 is success) and the `Fix:` lines.
- The pull request workflow: upload the artifact, then post the URL with `gh pr comment`.
- A rule: never put the token in a command line, a file in the repository, or a comment. Use the environment variable `FILESLOP_TOKEN` or the config file.

## Consequences

Positive:

- Agents share artifacts on pull requests without human help.
- One installation command for each agent environment.
- The skill and the client are in one repository. They change together.

Negative:

- The skill text must follow changes of the CLI. A review must check both.
- Each agent harness loads skills differently. We test only the common `SKILL.md` format.

## Alternatives considered

- An MCP server: more code and a running process. Rejected for v0.1.
- Instructions only in the README: agents do not load them automatically. Rejected.
