# ADR-003: Object store adapter with one S3-protocol implementation

Status: Accepted

Date: 2026-10-29

## Context

Fileslop must store files in AWS S3 or in Hetzner Object Storage.
Both services use the S3 protocol.
The AWS SDK has many dependencies (see [ADR-001](ADR-001.md)).
Tests must run without network access (see [ADR-014](ADR-014.md)).

## Decision

Define a port interface in the server:

```ts
interface ObjectStore {
  put(key, body, contentType, metadata): Promise<"created" | "exists">;
  get(key): Promise<StoredObject | null>;
}
```

- Implement one adapter, `S3Store`, for the S3 protocol.
- Sign each request with our own AWS Signature V4 implementation. Use `node:crypto` only.
- Buffer the body. Send the SHA-256 hash of the body as the signed payload hash.
- Put custom metadata in `x-amz-meta-*` headers. AWS limits user metadata to 2 KB. Our header limits (see [ADR-009](ADR-009.md)) keep the metadata below this limit.

The backends `aws_s3` and `hetzner` differ only in endpoint resolution:

| Backend   | Endpoint                                             | Signing region                    |
| --------- | ---------------------------------------------------- | --------------------------------- |
| `aws_s3`  | `https://<bucket>.s3.<region>.amazonaws.com`         | `FILESLOP_S3_REGION`              |
| `hetzner` | `https://<bucket>.<location>.your-objectstorage.com` | location (`fsn1`, `nbg1`, `hel1`) |

- The optional variable `FILESLOP_S3_ENDPOINT` overrides the endpoint.
- With the override, use path-style URLs: `<endpoint>/<bucket>/<key>`.
- Use the override for tests and for other S3-compatible stores.

## Consequences

Positive:

- No AWS SDK. No runtime dependencies.
- One adapter supports AWS, Hetzner, and other S3-compatible stores.
- Tests replace the store with a mock S3 HTTP server through the endpoint override.

Negative:

- We must maintain our own Signature V4 code. A unit test checks it against the official AWS example vector.
- A buffered body uses memory. See [ADR-011](ADR-011.md) for the size limit.
- A store that is not S3-compatible needs a new adapter.

## Alternatives considered

- AWS SDK v3: rejected because of dependencies.
- One adapter for each backend: the code is almost identical. Rejected.
- `UNSIGNED-PAYLOAD`: allows streaming, but is not necessary for buffered bodies. Kept as an upgrade path.
