# ADR-015: Development tooling

Status: Accepted

Date: 2026-10-29

## Context

The code base needs type checks, lint rules, and a consistent format.
Development dependencies also have supply-chain risk.
Attackers sometimes publish compromised package versions. The community often finds them within days.

## Decision

- Use TypeScript 6.0.
- Do not use TypeScript 7.0. typescript-eslint 8 supports only TypeScript versions lower than 6.1.
- Use ESLint 10 with the typescript-eslint `strict-type-checked` rules.
- Use Prettier 3 for formatting.
- Use pnpm as package manager.
- Set `minimumReleaseAge` to 3 days in pnpm. pnpm does not install a version that is younger than 3 days.
- Add these tools as development dependencies only.

## Consequences

Positive:

- Strict type-checked lint rules find many errors before tests run.
- One format for all files. No format discussions in reviews.
- The release age delay reduces the risk from compromised fresh releases.

Negative:

- We cannot use TypeScript 7.0 features until typescript-eslint supports it.
- Urgent security fixes in development dependencies arrive 3 days later. A maintainer can override the delay for one package.
- Type-checked lint rules are slower than simple lint rules.

## Alternatives considered

- Biome: one tool for lint and format, but fewer type-aware rules. Rejected.
- npm or Yarn: no `minimumReleaseAge` setting with the same behavior. Rejected.
