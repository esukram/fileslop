# ADR-001: Runtime is Node.js with native type stripping and no runtime dependencies

Status: Accepted

Date: 2026-10-29

## Context

Fileslop has a server and a client CLI. Both are small programs.
Each third-party package adds supply-chain risk.
A compromised package can steal tokens or object store credentials.
Node.js 24 and later can run TypeScript files directly with native type stripping.
The Node.js standard library has an HTTP server, cryptography, file access, argument parsing, `fetch`, and a test runner.

## Decision

- Use Node.js 24 or later. The target version is Node.js 26 LTS.
- Write all code in TypeScript.
- Run the server source files with Node.js native type stripping. Do not use a build step for the server.
- Use only `node:` standard library modules at runtime in the server and the client.
- Use these modules: `node:http`, `node:crypto`, `node:fs`, `node:util` (`parseArgs`), global `fetch`, and `node:test`.
- Do not add runtime dependencies to the server or the client.
- Use only TypeScript syntax that type stripping supports. Do not use `enum`, `namespace` with values, or parameter properties.

## Consequences

Positive:

- The supply-chain attack surface at runtime is zero third-party packages.
- Installation is fast. `npx -y fileslop` downloads one small package.
- No build step is necessary to run the server.
- Security updates come only from Node.js releases.

Negative:

- We write some code that a library usually supplies, for example AWS Signature V4 (see [ADR-003](ADR-003.md)).
- We must test this code ourselves.
- Type stripping does not support all TypeScript features.
- Node.js does not strip types in `node_modules`. The client package must be compiled (see [ADR-013](ADR-013.md)).

## Alternatives considered

- AWS SDK for JavaScript: many transitive dependencies. Rejected because of supply-chain risk.
- A web framework (Express, Fastify, Hono): not necessary for three routes. Rejected.
- Bun or Deno: smaller user base on servers and CI runners. Rejected for v0.1.
