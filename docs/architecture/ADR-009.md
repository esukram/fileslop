# ADR-009: Strict validation of upload headers

Status: Accepted

Date: 2026-10-29

## Context

The client sends the filename and optional metadata in HTTP headers.
The server uses the filename in the object key and in the public URL.
The server stores the metadata in `x-amz-meta-*` headers.
Unsafe values can cause path traversal, header injection, or broken URLs.

## Decision

The server accepts these headers:

| Header                     | Required | Pattern                               | Metadata key             |
| -------------------------- | -------- | ------------------------------------- | ------------------------ |
| `X-FS-Filename`            | Yes      | `^[A-Za-z0-9][A-Za-z0-9._-]{0,254}$`  | `fs-filename`            |
| `X-FS-Username`            | No       | `^[A-Za-z0-9][A-Za-z0-9._/-]{0,127}$` | `fs-username`            |
| `X-FS-Repository`          | No       | `^[A-Za-z0-9][A-Za-z0-9._/-]{0,127}$` | `fs-repository`          |
| `X-FS-Repository-Provider` | No       | `^[A-Za-z0-9][A-Za-z0-9._/-]{0,127}$` | `fs-repository-provider` |

- An invalid value gives status 400 with the error code `invalid_header`.
- A missing `X-FS-Filename` also gives status 400 with `invalid_header`.
- The server rejects invalid values. It does not rewrite them silently.
- The first character must be a letter or a digit. Thus a filename cannot start with `.` and cannot be `..`.
- The filename pattern has no `/`. Thus a filename cannot add a folder to the object key.
- `X-FS-Username` is a value that the client declares. The server stores the authenticated user separately as `fs-uploader` (see [ADR-006](ADR-006.md)).

## Consequences

Positive:

- No path traversal. No header injection. URLs need no encoding.
- The metadata stays below the AWS limit of 2 KB.
- The client gets a clear error. The stored value is the value that the client sent.

Negative:

- The server rejects filenames with spaces or non-ASCII characters. The client CLI replaces these characters in the default name (see [PRD-client-cli](../prds/PRD-client-cli.md)). A raw HTTP client must send a valid name.
- The server rejects repository names longer than 128 characters.

## Alternatives considered

- Rewrite invalid characters to `_`: the URL differs from the expected name. Rejected.
- Percent-encode any filename: complex, and risky in object keys. Rejected.
