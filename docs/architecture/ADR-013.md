# ADR-013: Client CLI design

Status: Accepted

Date: 2026-10-29

## Context

Humans and AI agents upload files from a shell.
Agents run commands without a prompt. They read stdout, stderr, and the exit code.
Agents must recover from errors without human help.
Node.js does not strip TypeScript types in `node_modules` (see [ADR-001](ADR-001.md)).

## Decision

- The npm package name is `fileslop`.
- Users run the client with `npx -y fileslop`.
- Compile the client with `tsc` to `dist/`. Publish only the compiled JavaScript.

Commands:

| Command                                                                               | Function                                                                    |
| ------------------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| `upload <file> [--type] [--name] [--username] [--repository] [--provider] [--no-git]` | Uploads a file and prints the server response.                              |
| `config`                                                                              | Prints the effective configuration and its source as JSON. Masks the token. |
| `help [command]`                                                                      | Shows help for all commands or for one command.                             |
| `--version`                                                                           | Shows the client version.                                                   |

- Parse arguments with `util.parseArgs`.
- Without `--name`, make the filename from the base name of the file. Replace characters that the server does not accept with `-`.
- If `--username`, `--repository`, or `--provider` is absent, read `git remote get-url origin`. Derive the missing values from the remote URL.
- Do not send a value from git that the server does not accept. `--no-git` stops the read of the git remote.
- If git is not available, send no repository headers.
- Print the server JSON response on stdout.
- Print errors on stderr.
- Each error message has a line that starts with `Fix:`. The line tells the user or agent the next step.

Exit codes:

| Code | Meaning                             |
| ---- | ----------------------------------- |
| 0    | Success.                            |
| 1    | Upload, server, or network failure. |
| 2    | Usage error or configuration error. |

## Consequences

Positive:

- Agents can parse stdout as JSON.
- Agents can decide on the next step from the exit code and the `Fix:` line.
- `npx -y` needs no global installation.

Negative:

- The client package needs a build step before publication.
- The extension table for content types (see [ADR-007](ADR-007.md)) is part of the client.
- `npx` downloads the package on the first run. This needs network access to the npm registry.

## Alternatives considered

- A shell script with `curl`: no content type map, no config file, poor errors. Rejected.
- A single executable binary: needs a build per platform. Rejected for v0.1.
